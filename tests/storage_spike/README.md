# Изолированная проверка Room + SQLCipher

Это отдельный тестовый Android-проект с applicationId `ai.memora.storageprobe`, не часть Memora и не P1-миграция. Он создаёт случайную тестовую БД только в собственном sandbox с вымышленным текстом и после теста удаляет только эту БД. Никогда не указывать пути приложения Memora и не использовать реальные данные. Код теста не доказывает безопасность Keystore, процессной памяти, WAL, backup или миграции.

Первичный изолированный spike проверял AGP 8.13.0, Kotlin 2.1.20, KSP 2.1.20-1.0.32, Room 2.8.5, `sqlcipher-android` 4.20.0 и AndroidX SQLite 2.7.0 на Android 14 API 34 arm64 emulator. С тех пор P1 integration добавила Room 2 + SQLCipher в приложение, но пользовательские workflows и legacy stores не переключены. Основное приложение использует KAPT, потому что повторный KSP import schema завершался `AbstractMethodError`; отдельный spike остаётся зафиксированным исследовательским артефактом. Перед повтором сверить версии и следовать ADR-011.

Сборка из `apps/android` с установленным Android SDK:

```sh
./gradlew -p ../../tests/storage_spike assembleDebug assembleDebugAndroidTest --no-daemon
```

Инструментальный тест запускать только на заведомо отдельном синтетическом эмуляторе после проверки его AVD: явно указывать его serial для каждого `adb` вызова, установить **оба APK этого проекта** и запустить `ai.memora.storageprobe.test/androidx.test.runner.AndroidJUnitRunner`. Не запускать `connectedDebugAndroidTest` на телефоне владельца и не использовать пакеты `ai.memora.app` или его тестовый runner.

На изолированном эмуляторе тест проверяет сохранение/повторное открытие с правильным случайным ключом, отказ с неправильным ключом, отсутствие одного контрольного открытого текста и обычного заголовка SQLite в закрытом основном файле, а также rollback транзакции. Это ограниченное свидетельство; оно не доказывает полную защиту всех файлов или восстановление при сбое питания.
