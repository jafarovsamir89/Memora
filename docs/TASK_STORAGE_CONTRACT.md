# Черновик хранилища списка дел

**Дата:** 2026-10-30; частичная работа MEM-04.06, MEM-05.07, MEM-06.09 и MEM-11.01. Разработка и испытания только на синтетических данных. Это не допуск личного пилота.

События задач хранятся одним зашифрованным файлом во внутреннем каталоге приложения; система резервного копирования в манифесте отключена. Ключ создаётся Android Keystore, содержимое защищается AES-GCM со случайным IV, версия формата проверяется до чтения. Файл записывается во временный зашифрованный файл с синхронизацией, затем заменяется атомарным перемещением в том же каталоге; при отсутствии поддержки операция отклоняется. Ошибка чтения, проверки целостности, ключа или формата не превращается в пустой список и не разрешает перезапись. Потеря ключа или удаление приложения может сделать данные невосстановимыми: экспорт доступен, но обратный импорт и пользовательское восстановление ещё не разработаны. Аппаратная защита и биометрия не предполагаются автоматически.

События последовательно воспроизводятся через доменные правила. При совпадении идентификатора команды и идентичном событии повтор не создаёт второй эффект; тот же ID с иным содержимым — конфликт. Одинаковые названия с разными идентификаторами не считаются повтором. Лимиты размера и числа событий защищают прототип от неконтролируемого роста; превышение — видимая ошибка. Операции сериализуются в одном процессе; для нескольких процессов и серверной синхронизации этот протокол не является решением. Исходные тексты в диагностику не выводятся.

## Проверки до включения в пользовательский путь

| ID | Вход | Ожидаемое поведение |
| --- | --- | --- |
| ST01 | Запись созданного события, новый экземпляр хранилища | Восстановлена та же версия задачи; на диске отсутствует исходный текст. |
| ST02 | Одно событие записано дважды | Второй вызов возвращает повтор без новой записи; другая команда сохраняется независимо. |
| ST03 | Тот же ID команды с иным содержимым или устаревшая версия | Конфликт, прежний файл и данные сохраняются. |
| ST04 | Повреждённый шифртекст или неверный ключ | Чтение и последующая запись завершаются ошибкой, данные не заменяются пустыми. |
| ST05 | Перезапуск и попытка восстановить отсутствующий ключ | Новый ключ не создаётся поверх существующих данных, возвращается ошибка. |
| ST06 | Ввести синтетическую задачу в тестовом разделе, отметить её выполненной | Название и статус записаны локально; при ошибке записи экран не сообщает успех. Раздел явно обозначен как тестовый. |
| ST07 | Изменить задачу, перезапустить хранилище | Новая версия восстанавливается, предыдущее изменение входит в экспорт. |
| ST08 | Удалить задачу и повторить старую команду | Все события этой задачи исключаются из текущего файла и экспорта; повтор старого создания отклоняется по сохраняемому ID без текста задачи. Остальные задачи сохраняются. |
| ST09 | Удалить все задачи после подтверждения | Текущие события удаляются, остаются только ID для защиты от повторов; внешние копии экспорта не удаляются. Ошибка записи не сообщается как успех. |
| ST10 | Экспорт через системный выбор файла | Экспорт содержит только доступные задачи и историю в версионированном JSON; файл открытый, его размещение и сохранность контролирует пользователь. Отмена не создаёт файл. |

Исполняемые синтетические тесты проверяют перечисленные случаи на JVM; отдельные проверки Android Keystore, атомарной замены и сценариев сбоя питания на устройстве ещё нужны. Экспорт и удаление реализованы для текущего тестового списка; их полная приёмка, проверка резервирования и модель угроз остаются открытыми по MEM-05.07/05.08/06.09. Серверные гарантии и системное восстановление не проверяются данным прототипом.
