# Черновик доменного контракта: первый локальный путь

**Состояние:** начат MEM-01.10, 2026-10-30. Это проектируемые структуры и проверки, а не схема базы или работающий код. Контракт охватывает первый путь текст → предложение → подтверждение → сохранение → поиск → исправление; полные схемы денег, прав, удаления, времени, совместимости и серверной адаптации остаются открытыми. Основания: [ADR-001](adr/ADR-001-native-architecture.md), [ADR-002](adr/ADR-002-memory-provenance.md), [план](ENGINEERING_PLAN.md).

## Словарь

| Понятие | Назначение и минимальные ограничения |
| --- | --- |
| Actor | Кто инициировал действие. Локальный ID не доказывает сетевую личность; автор, владелец и устройство не взаимозаменяемы. |
| Scope | Личная или общая область. Каждая операция, источник и результат имеют область; права на связанные объекты проверяются отдельно. |
| Capture | Полученный с разрешения исходный текст или ссылка на другой вид исходника, ID, область, время записи и версия. Аудио не придумывается для текста. |
| SourceRevision | Неизменяемая версия доступного текста/транскрипта с устойчивым ID. Исправление создаёт новую версию; удаление выполняется по отдельной политике. |
| Evidence | Ссылка на конкретную версию исходника и диапазон либо указание на ручное действие. Старый диапазон не применяется к новой версии. |
| Proposal | Типизированное предложение с ID, версией, областью, предполагаемым эффектом, основаниями и состоянием; не является применённым фактом. |
| Approval | Согласие конкретного автора на конкретные ID, версию и содержание предложения, его область и существенные последствия. |
| Command | Намерение применить операцию с ID/ключом повтора, областью, неизменяемым содержимым, ожидаемой версией и ссылкой на обязательное подтверждение. |
| Event | Зафиксированное доменное изменение с ID, порядком внутри области, автором и ссылками на команду и допустимые основания. История подчиняется удалению личных данных. |
| Projection | Производное состояние, перестраиваемое из разрешённой канонической истории и исходных записей; не является самостоятельным доказательством. |
| QueryResult | Ответ с разрешённой областью, основанием, периодом и признаком отсутствия или неполноты сведений; не раскрывает запрещённые данные. |

Формальный формат ID, границы диапазонов Unicode, порядок событий, ограничения длины и сериализация будут определены до реализации; их отсутствие нельзя подменять платформенными предположениями. Времена события, захвата, обработки и серверного получения различны, неизвестное остаётся неизвестным.

## Переходы первого пути

1. Разрешённый захват получает ID и версию; сам по себе он не является подтверждением интерпретации.
2. Разбор создаёт предложение, связанное с конкретной версией исходника. Недостаток данных переводит его в уточнение; отклонение не создаёт доменного эффекта.
3. Существенное исправление создаёт новую версию предложения. Подтверждение прежней версии на неё не переносится.
4. Команда применения проверяет точное подтверждение, права, зависимости и ожидаемую версию. При успехе событие и результат команды сохраняются атомарно. При конфликте или сбое нельзя сообщать об успешном применении.
5. Запрос читает только разрешённые актуальные данные и выдаёт доступное основание либо честно сообщает его отсутствие. Проекция не может дополнять неизвестное выдуманными сведениями.
6. Исправление канонического содержимого — новая команда и событие со связью с предыдущей версией; зависимые представления пересчитываются. Если источник или данные удалены, действует отдельно определённый охват удаления.

Команда и предложение имеют отдельные состояния; подтверждённое предложение ещё не обязательно применено. Повтор одной команды не создаёт второй эффект, разные команды не объединяются из-за сходства. Схемы ошибок, отмены, конкуренции, границы транзакций и внешние эффекты уточняются в MEM-01.11/13.

## Синтетические примеры будущих проверок

| Вход и изменение | Ожидаемый результат |
| --- | --- |
| Пользователь ввёл «Книга на полке». Создано предложение версии 1, затем он изменил «полке» на «столе». | Источник и предложение версии 2 не наследуют подтверждение версии 1; прежний результат обработки нельзя применить к новой версии. |
| Пользователь подтвердил точную версию и дважды отправил одну команду. | Одно доменное изменение, повтор возвращает тот же результат после проверки прав. |
| Пользователь спросил о записи, которой нет в доступной области. | Ответ «нет сведений»; запись и её предполагаемый источник не выдумываются. |
| Исправлен сохранённый факт. | Новое корректирующее событие и обновлённая проекция с сохранением допустимого происхождения. |

Это описание будущих проверок, не исполненные тесты. Денежные, временные и многопользовательские схемы, полная машина состояний и контракты удаления остаются незавершёнными; MEM-01.10 не закрыта.
