# Первый APK: нативный UI-каркас Memora

**Дата:** 2026-10-29, Asia/Baku. **Основание:** прямое указание владельца сначала создать APK-каркас UI и дизайн, затем вернуться к функциональным задачам TODO. ADR-001–009 позднее оформлены; ограничения этой демонстрационной сборки от этого не исчезают.

## Граница этой сборки

Каркас на Kotlin / Jetpack Compose / Material 3 — код нативного Android-приложения, предназначенный для проверки экранов и взаимодействий. Целевое устройство владельца: Redmi Note, Android **13** (владелец исправил первоначальное сообщение об Android 12), 6 ГБ RAM, 128 ГБ накопитель, Helio G96. Точный номер модели не установлен. Минимальная версия сборки — Android 8 / API 26; API 33 соответствует Android 13.

Есть главная, память с поиском/фильтрами, просмотр примера с исходным текстом, дела с переключением статуса, каталог разделов, входящие, финансы, люди, проекты, макет диалога и настройки. Нижняя навигация: **Сегодня → Память → Запись → Дела → Ещё**. Финансы, люди, проекты и входящие доступны через «Ещё»; настройки также доступны из главной.

Примеры явно вымышлены. Тестовый текстовый черновик сохраняется локально и после явного действия попадает во входящие как источник без AI-обработки. Во входящих есть локальный поиск по тексту, фильтры активных/архивных и групповое изменение архивного статуса выбранных записей; содержание не удаляется. Отдельная запись удаляется после показа текста и подтверждения; локальные записи и черновик экспортируются в открытый JSON через системный выбор файла. Прежние экспортные копии остаются. Добавлен ограниченный импорт этого формата с предпросмотром, проверкой конфликтов и явным подтверждением; после переустановки или на другом устройстве старый файл может содержать удалённые сведения, поскольку маркеры удаления не экспортируются. Экран предупреждает об использовании только вымышленных данных; полный импорт и допуск личных данных не готовы. На эмуляторе Android 14 проверены восстановление после force-stop, поворот, экспорт, удаление, тестовый импорт, поиск и архивирование; физический телефон и сбой питания не проверены. Это не полноценная долговременная память. Язык и тема сохраняются локально; отдельный экран памяти ищет только демонстрационные записи. Прежние примеры дел меняют только состояние UI. Отдельный тестовый список позволяет добавлять, редактировать и удалять задачи, хранить срок и подписи человека/проекта, включать напоминание и экспортировать историю; ограничения — [хранение](TASK_STORAGE_CONTRACT.md), [напоминания](TASK_REMINDER_CONTRACT.md). Локальный голосовой ввод черновика и отдельный эксперимент Google Live описаны в [контракте ввода](VOICE_INPUT_PROTOTYPE.md) и [контракте облачного разговора](CLOUD_VOICE_TEST_CONTRACT.md).

Приложение использует разрешение сети для экспериментального Google AI; общий доступ к файлам и контактам не запрашивается. Для голосового ввода микрофон запрашивается после действия и отдельного согласия на облачный поток; для напоминаний — разрешение на уведомления. В настройках видны доступ к микрофону и доступность уведомлений задач с переходами в Android; при отказе от микрофона доступен текстовый ввод. Язык и тема сохраняются локально; остальные параметры профиля ещё не реализованы. Восстановление расписания использует системное событие после загрузки; работоспособность на телефоне ещё не проверена. System backup отключён. Не вводить в эту сборку реальные личные/финансовые сведения: прототипы ещё не прошли допуск и проверку устройства. Авторизация, полноценная STT-приёмка, команды/подтверждения, денежный журнал и сервер здесь не реализованы; тестовые Google AI и облачный голос действуют в ограниченном объёме.

## Дизайн

Направление: спокойный повседневный помощник, тёплый фон, просторная типографика, один фиолетовый акцент, небольшое число основных разделов. Системный sans-serif поддерживает RU/AZ/EN и не требует загрузки шрифтов. Рекомендации UI/UX Pro Max применены к нативным Material-компонентам; веб-паттерны и предложенная пара декоративных шрифтов не переносились в приложение.

| Токен | Светлая тема | Тёмная тема |
| --- | --- | --- |
| Фон | `#F8F7F4` | `#17171C` |
| Поверхность | `#FFFFFF` | `#222229` |
| Основной текст | `#252432` | `#F1EFF6` |
| Вторичный текст | `#6B6875` | `#B1ADB9` |
| Акцент | `#6650B8` | `#BCA9FF` |
| Мягкий акцент | `#EEEBFA` | `#342C4A` |

Шаг отступов — 4/8 dp, поля телефона — 24 dp, ширина контента ограничена 720 dp на больших экранах. Скругления карточек — 24 dp, поля — 18–20 dp. Заголовки 34/28/22 sp, основной текст 16/14 sp, вспомогательный 12 sp, подписи 11 sp. Цвета централизованы в `ui/Theme.kt`; иконки — единая собственная контурная система `ui/Icons.kt`. Все интерактивные компоненты используют Material feedback, стандартные роли и подписи. Автоматических декоративных анимаций нет; системные компоненты учитывают масштаб анимации ОС.

Русский язык выбран по умолчанию, доступны английский и азербайджанский; переключение применяется к строкам интерфейса и датам. Точность переводов требует отдельной пользовательской проверки. Увеличенный шрифт и небольшие экраны используют перенос строк и вертикальную прокрутку; фильтры прокручиваются горизонтально.

## Техническое решение для каркаса

Исходники — [apps/android](../apps/android). Фиксированы AGP 8.13.0, Gradle 8.13, Kotlin/Compose compiler 2.1.20, Compose BOM 2025.05.01, Activity Compose 1.10.1, JDK 17, compile/target SDK 36. Выбрана совместимая фиксированная комбинация, а не требование всегда использовать последние версии. Gradle wrapper включён в репозиторий и имеет проверенную SHA-256 дистрибутива. Дизайн и состояние примеров отделены от Activity; канонического домена/БД пока нет. Это не ADR-001/ADR-002 полноценной системы.

Новый приоритет владельца разрешает обратимый UI-каркас до завершения доменных контрактов. Подключение настоящего сохранения, AI, денег и прав возвращается к соответствующим задачам TODO и необходимым ADR. Порядок «нативный функционал → полная приёмка → серверная адаптация» сохраняется.

## Сборка и проверка

Установить JDK 17, Android SDK platform 36 и build tools 35.0.0. Указать путь SDK через `ANDROID_HOME` либо локальный `apps/android/local.properties` с `sdk.dir=...` (на Windows, например, `sdk.dir=C\:/android-sdk`); файл не коммитится. Из `apps/android`:

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`; копия для передачи — `artifacts/Memora-0.1.0-ui-debug.apk` от корня репозитория. Это debug-подпись для внутренней проверки, не магазинный релиз. Исходные APK, отчёты и скриншоты исключены из Git как генерируемые артефакты.

JVM-проверки Robolectric исполняют Android API 33: переходы/поиск/источник, добавление записи, восстановление UI, статус дела, смена темы/языка, финансовое демо и состояние голоса. В первоначальной проверке `UiShellTest` пройдены 9/9; новые результаты полного набора — в журнале. Native graphics используется для 11 PNG экранов; текущий путь вывода — `apps/android/app/build/test-screenshots`, включая 360×800 dp с масштабом текста 1.4 и альбомный 960×600 dp. Изображения UI-каркаса просмотрены. Это симуляция Android; изображения не являются скриншотами Redmi.

Для снимков используется отрисовка настоящей View-иерархии на Canvas через native graphics: стандартный `captureToImage()` в этой среде ждёт реальный кадр и завершается таймаутом ([известное ограничение](https://github.com/robolectric/robolectric/issues/8071)). Первоначальный сбой захвата исправлен в тестовой инфраструктуре; assertions приложения не отключались, baseline lint не создавался.

По последующему прямому запросу владельца APK установлен через ADB и запущен на подключённом **2201117SG / Android 13 / API 33**, экран 1080×2400, density 440. Установка — `Success`, запуск MainActivity — `Status: ok`; в проверенном срезе AndroidRuntime процесса ошибок нет. Это проверка установки/запуска, а не полная приёмка интерфейса на устройстве. Личные скриншоты телефона не включаются в артефакты проекта.

При проверке APK на телефоне: установить → пройти все пять пунктов навигации → открыть источник → добавить обезличенный черновик → проверить темы и языки → увеличить системный шрифт → повернуть экран → проверить отсутствие наложения на системные панели и клавиатуру. Зафиксировать наблюдения, прежде чем принимать дизайн. Завершение этого каркаса не закрывает функциональную приёмку MEM-14.09.
