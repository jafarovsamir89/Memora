# Production AI and Voice Architecture

**Нативная реализация 2026-10-31:** AZ — главный язык, поддерживаются RU и смешанная речь. По уточнению владельца реальные испытания пока только Gemini; Scribe/Groq остаются сравнением. Разделены Live-диалог, STT законченной заметки `gemini-3.5-transcribe-live`, ограниченное восстановление письменности текстовым Gemini и обычный текстовый ответ. STT использует тот же Firebase-прокси и App Check с явными AZ/RU подсказками; SDK 18.1.0 не предоставляет эти поля, поэтому применён узкий протокольный адаптер. Общий generateContent audio understanding исключён из заметки после неуспешных проб. Предложение письменности не является новым доказательством: исходный STT доступен, числа/отрицания/слова защищены проверками, итог подтверждает человек. Системный TTS отказывает при подмене языка голоса. Решение/альтернативы/приёмка — [AZERBAIJANI_VOICE_PLAN.md](AZERBAIJANI_VOICE_PLAN.md); результаты — ACT-0035.

**Порядок реализации, 2026-10-29:** сначала нативное Android-приложение с локальными данными и доменной валидацией; после тестирования и подтверждения всего функционала — адаптация к серверной инфраструктуре. AI gateway и серверная конфигурация ниже относятся к будущему серверному этапу. Безопасный способ доступа к STT/LLM/TTS на нативном этапе и хранение ключей определяются ADR-007 до подключения: общий секрет нельзя встраивать в распространяемый APK. Нативное приложение не означает обязательную работу моделей на устройстве; собственный backend до нативной приёмки не является предпосылкой разработки. Основание — раздел 1.1 [ENGINEERING_PLAN.md](ENGINEERING_PLAN.md).

## Multi-provider architecture
AI Gateway выбирает модели по типу операции, языку, качеству, цене, latency и политике данных. Возможные STT: Groq Whisper, ElevenLabs Scribe, Google, OpenAI; LLM: GPT-OSS, Gemini, Mistral, DeepSeek, OpenAI; TTS: системный Android/iOS и облачные. **Список кандидатов, не контракт:** цены, языки, API и условия проверяются перед интеграцией.

## Separate pipelines
- Speech-to-text (STT): получение аудио, кодек/нормализация, детекция языка, выравнивание сегментов, транскрипт и confidence; повтор более качественным провайдером при низкой уверенности; пользовательское исправление.
- Text extraction: JSON Schema структурированные факты/намерения, классификация, даты, суммы, валюта, имена, связи, цитаты на источник.
- Context resolution: поиск известных сущностей, генерация кандидатов связей без автоматического слияния при неоднозначности.
- Deterministic validation: проверка правил, разрешений, дат/валют/бизнес-инвариантов, idempotency; auto-commit безопасного либо очередь подтверждения.
- Retrieval/response: tenant-scoped hybrid search + exact SQL + bounded LLM composition; ответ с источниками и уровнем неопределённости.
- TTS: локальная озвучка при поддержке нужного языка и пользователя; cloud TTS по желанию; realtime voice — отдельно управляемый тарифный режим.

## Accuracy tests: mandatory languages
RU, AZ, EN и RU/AZ code-switching; разговорная и шумная речь, имена, топонимы, BMW/технические названия, даты и манаты. Проверять не только word error rate: **critical slot accuracy** (кто кому должен, дата, сумма, валюта, знак, отрицание, обещание vs факт) и долю ложных записей. Строить анонимизированный или явно разрешённый test corpus с эталонами; закрывать доступ к личным аудио.

## Robust model I/O
JSON schema + детерминированная доменная проверка (локальная на нативном этапе, независимая серверная после перехода), ограниченное число retry, model/provider version pinning, fallback только в пределах разрешённой data residency и согласия. Не отправлять всю историю в каждый запрос. Извлечённый контент и документы — недоверенные данные: prompt injection не имеет прав вызывать инструменты.

## Cost controller
Учитывать input/output/reasoning/cache tokens, аудиоминуты, TTS-символы/аудиотокены, провайдер, retry, стоимость по версии тарифа, tenant, тип операции. Квоты, budget alerts, degraded mode, кэш безопасных результатов, batching где применимо, cap на контекст. Стоимость считать как actual usage, а не сумму из предположений.

## Model evaluation & release
Dataset по сценарию → offline score → human review critical errors → canary on consented test accounts → regression monitoring → roll back. Никогда не делать прямой вывод о точности из цен или рекламных утверждений провайдера.

## Уточнения для ранней разработки

По запросу владельца начат [тестовый голосовой ввод](VOICE_INPUT_PROTOTYPE.md) через системный on-device API Android: только после явного нажатия и разрешения, с отменой и редактируемым черновиком. Доступность моделей RU/AZ/EN пока не подтверждена. Добавлен экспериментальный маршрут Firebase AI Logic → Gemini Developer API с отдельным подтверждением передачи текста; один синтетический текстовый запрос получил ответ Google на тестовом телефоне. Добавлена опциональная системная озвучка с предупреждением о возможном использовании сети; её реальная работа ещё проверяется. [Текущий статус и ограничения](VOICE_ASSISTANT_NEXT.md). Память и инструменты к модели не подключены; реальные личные данные не допущены.

Исследование RU/AZ/EN и смешанной речи начинается параллельно доменным контрактам; полноценная приёмка включает реальное Android-устройство и путь до сохранённого состояния. Наборы настройки и независимой проверки разделяются. Confidence модели не является готовой вероятностью правильности: автоматическое сохранение и fallback определяются проверенной политикой риска, языковыми метриками и разрешёнными маршрутами данных. Личный словарь помогает распознаванию, но не разрешает автоматическое слияние одноимённых людей.

Первоначально предлагается проверить основной маршрут обработки, общий контракт замены провайдера и понятное поведение при отказе. Конкретный поставщик и сложная динамическая маршрутизация ещё не выбраны. Сохранённые события восстанавливаются без повторного AI-извлечения; новый разбор является новой версией предложения. Подробности — [ENGINEERING_PLAN.md](ENGINEERING_PLAN.md) и [QUALITY_AND_ACCEPTANCE.md](QUALITY_AND_ACCEPTANCE.md).

По решению владельца ценовые вопросы сейчас полностью отложены. Разделы о стоимости выше остаются контекстом полного продукта, а не поручением начать текущие расчёты.
