# ADR-003: владение, доступ и границы автономной работы

**Статус:** инженерное решение для проектирования, 2026-10-30; MEM-01.03. Реализация и проверки предстоят. Основания: [безопасность](../SECURITY_AND_PRIVACY.md), [данные](../DOMAIN_AND_DATA.md), [сценарии](../SCENARIOS.md), [ADR-001](ADR-001-native-architecture.md).

## Контекст и решение

Первый этап — одно нативное приложение с локальными данными, без собственного сервера и серверной учётной записи. Локальный пользователь, устройство и область данных имеют устойчивые идентификаторы; их нельзя считать доказательством личности или удалённой авторизацией. Владельца, автора изменения и область доступа храним раздельно. До использования личных данных необходимы проверенные локальная защита и жизненный цикл данных, включая экспорт/удаление; конкретные механизмы защиты устройства и ключей выбираются и проверяются отдельно.

Далее серверные учётные записи, подлинность, участники, приглашения и роли реализуются только после MEM-14.09. Сервер проверяет каждую операцию и не доверяет заявленным клиентом owner, роли или области. Изоляция tenant и проверка разрешений в пространстве обязательны, однако принадлежность к tenant не открывает все личные данные. Не переносим локальное владение на сервер автоматически: при миграции сопоставление пользователя и областей должно быть явно подтверждено и проверено.

## Области и полномочия

Личная область видна владельцу по действующей политике; общая область — участникам с действующим разрешением. Новая запись по умолчанию личная: публикация и перенос в общее пространство являются отдельными явными действиями с проверкой зависимых источников. Доступ к объекту не даёт автоматически доступ к источнику, вложению или связанному личному объекту; перед раскрытием проверяется каждый раскрываемый ресурс. Ответ может указать, что доступные сведения неполны, не раскрывая содержимое или существование защищённых записей без права на это.

Для общего пространства проектируем минимальные роли: владелец управляет участниками и политикой; редактор читает и изменяет разрешённые данные; читатель только читает. Удаление области, экспорт, приглашения и внешние действия требуют отдельных разрешений, а не выводятся только из возможности редактирования. Фактическая матрица прав и детали передачи владения определяются MEM-01.11; до неё не выдавать общий доступ. Последнего владельца нельзя удалить без предусмотренного безопасного перехода владения.

Проверки охватывают чтение, поиск, историю, источник, экспорт, уведомления, AI-контекст и команды; проводятся при начале операции и повторно перед выдачей результата или применением отложенного действия. На недостаточность прав возвращается безопасный отказ, не содержащий чужие данные. Для операций над несколькими записями каждая запись проверяется отдельно; частичный результат допустим только с явным статусом и без раскрытия запрещённого содержимого.

## Отзыв и автономный кэш

На серверном этапе после обнаружения отзыва клиент прекращает выдачу защищённого содержимого и инвалидирует соответствующие кэши, поисковые индексы, ожидающие команды и результаты обработки; сохранение и удаление подчиняются ADR-006. Кэш общей области разрешён только при наличии установленного срока офлайн-доступа и реализованной проверяемой политики. Числовой срок и устойчивость к изменению часов ещё не определены: до этого автономное использование общей области запрещено. Личные локальные данные не получают сетевой зависимости только из-за этого будущего правила.

Недоступность сервера после истечения срока доступа не даёт продолжать чтение общей области. Уже скачанные данные на отключённом устройстве и выданный экспорт нельзя гарантированно отозвать дистанционно; пользователь должен знать пределы до предоставления доступа. Для синхронизации предусмотрены повторная проверка полномочий и разрешение конфликтов по ADR-005; UI не объявляет удалённое удаление завершённым по одной локальной операции.

## Альтернативы и последствия

Одна роль на весь tenant отклонена из-за утечки личных данных. Только UI-проверки отклонены: интерфейс и кэш нельзя считать доверенной серверной границей. Неограниченный офлайн-доступ к общим данным отклонён из-за невозможности своевременного отзыва. Выбранная модель требует явной матрицы, миграции и проверок на сервере; её наличие в документе не обеспечивает защиту приложения.

## Будущие проверки

| Сценарий | Ожидаемый результат |
| --- | --- |
| S17/S21 | Читатель не изменяет данные, участник не видит личную запись другого пользователя; разрешение на запись не раскрывает закрытый источник. |
| S35 | Отзыв между началом поиска/экспорта и выдачей предотвращает раскрытие; после обнаружения отзыва локальный кэш очищается по политике. |
| Офлайн | Без установленного и действительного разрешения общие данные не показываются; недостижимое устройство и экспорт не обещаются удалёнными. |
| Миграция | Не сопоставленная владельцу область не импортируется в произвольный аккаунт; права и идентичность проверяются отдельно на реальном сервере. |

Эти сценарии не выполнены. Конкретные протоколы сессий, матрица операций, сроки кэша и средства защиты остаются открыты до реализации и испытаний.
