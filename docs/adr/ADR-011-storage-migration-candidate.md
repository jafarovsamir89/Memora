# ADR-011: кандидат защищённого хранилища и контроль миграции

**Статус:** P0 / MEM-12.10 закрыт по контрактам/решениям; P1 / MEM-12.11 реализован на synthetic/test DB, приёмка остаётся открытой на 2026-11-01. Room schema v6 включает P2 recovery journal, изолированные P3–P6 domain tables и finance scope. Синтетические миграции/операции прошли на API34, физическом Redmi Android13 и API26 эмуляторе. На Redmi/API26 проверены неверный/отсутствующий ключ, отсутствующая envelope, повреждённый encrypted DB и отказ без перезаписи/потери тестовой записи. На этих двух средах также проверено, что SQLCipher DB закрыта без plaintext-маркера; `journal_mode` наблюдался как `delete`, WAL/SHM отсутствуют и остаются выключенными. Synthetic forced process death посреди незакоммиченной транзакции на Redmi/API26 сохранил committed row, откатил uncommitted row и успешно очистил отдельную probe DB после reopen. Это не проверка hard crash, питания или дисковых отказов. Release APK/AAB собраны и ABI/size измерены; артефакт APK unsigned. `allowBackup=false` и backup/transfer exclusions подтверждены merged manifest. Ещё открыты key rotation/recovery/uninstall, операционное restore, license review и signed release package. App workflows не переключены, пользовательские данные не мигрировались; P3–P6 foundation не подключён к UI/agent runtime. См. ACT-0066–0068; P2/P3–P6 исторические подробности — ACT-0063/0064. Связан с [ADR-010](ADR-010-agent-contract.md), [ADR-001](ADR-001-native-architecture.md), [ADR-006](ADR-006-retention-and-deletion.md) и разделом 4 [руководства](../AI_AGENT_IMPLEMENTATION.md).

## Кандидат и фактические источники

Инженерная цель — единая локальная транзакционная SQLite-база, Room 2 + SQLCipher Android + ключ БД, обёрнутый ключом Android Keystore, и независимые доменные интерфейсы. P1 интеграционный стек: Kotlin 2.1.20 / AGP 8.13.0 / Gradle 8.13 / KAPT 2.1.20 / Room 2.8.5 через `SupportOpenHelperFactory` / SQLCipher Android 4.20.0 / AndroidX SQLite 2.7.0 / Room Gradle Plugin 2.8.5; minSdk остаётся 26. Отдельный spike использовал KSP, но основной проект перешёл на KAPT из-за повторяемого schema import failure. Официальная Room документация описывает schema export для KAPT и Room Gradle Plugin; SQLCipher публикует артефакт [4.20.0 в Maven Central](https://repo.maven.apache.org/maven2/net/zetetic/sqlcipher-android/4.20.0/sqlcipher-android-4.20.0.pom) и описывает Room 2 `SupportOpenHelperFactory` в [официальном репозитории](https://github.com/sqlcipher/sqlcipher-android). Сборки и отдельный API 34 arm64 synthetic probe прошли. Это не выпускное одобрение: до переноса проверить API 26, Android 13 Redmi Note, каждый доставляемый ABI, Keystore/потерю ключа, WAL/SHM, crash recovery, backup exclusion, размер APK и лицензии.

На 2026-10-31 [страница Room](https://developer.android.com/jetpack/androidx/releases/room) указывает stable Room 2.8.5 и описывает schema export для KAPT/Room Gradle Plugin. [Официальный SQLCipher for Android](https://github.com/sqlcipher/sqlcipher-android) документирует поддержку API/ABI и различные пути Room 2 (`SupportOpenHelperFactory`) и Room 3 (`SQLCipherDriver`). [Документация миграции Room 2→3](https://developer.android.com/training/data-storage/room/migration-2-to-3) описывает отдельную модель driver API Room 3. Для P1 закреплён Room 2 adapter, собранный в приложении и проверенный synthetic probe на API 34; API 26/33/36, все релизные ABI, Keystore, размер и лицензии до переноса/выпуска всё равно нуждаются в проверке. Не смешивать API поколений и не использовать незашифрованную SQLite как аварийный обход.

**Изолированный эксперимент:** отдельный [storage spike](../../tests/storage_spike/README.md) с AGP 8.13.0, Kotlin 2.1.20, KSP 2.1.20-1.0.32, Room 2.8.5, SQLCipher Android 4.20.0 и AndroidX SQLite 2.7.0 собрался и прошёл один синтетический instrumented-тест на Android 14 arm64 emulator: правильный/неправильный ключ, повторное открытие и rollback. В основном закрытом файле не найдены контрольный открытый текст и стандартный заголовок SQLite. APK эксперимента содержит четыре заявленные ABI и занимает около 9,3 МиБ; AGP сообщил, что `libsqlcipher.so` упакована без stripping. Это ограниченная проверка кандидата, не доказательство совместимости всех ABI, размеров итогового APK, Keystore, отсутствия текста в WAL/SHM/логах, безопасности бэкапов или целостности миграции. Эксперимент не подключён к Memora. Условия лицензии и замечания для поставки необходимо отдельно проверить для конкретного артефакта и зависимостей до распространения.

## Зафиксированные legacy-источники Android

| Store | Текущий файл/тип | Содержимое и инварианты переноса |
| --- | --- | --- |
| `EncryptedCaptureStore` | `files/captures-prototype.bin`, magic `MC\x01`, AES-GCM; internal JSON schema 1–5, export/import `memora-captures` schema 1–3 | draft/version; capture command ID/origin/archive/organization version; source IDs/scopes, все revision IDs/numbers/text/timestamps; tombstones с исходной и прежними revision IDs. Preserve supported formats exactly; unknown schema → quarantine. |
| `EncryptedTaskStore` | `files/tasks-prototype.bin`, magic `MT\x01`, AES-GCM; internal snapshot schema 2, historical JSON array, export `memora-tasks` schema 1 | ordered Task events, task/command IDs, scope/actor, due-local/zone, versions/completion и deleted IDs. Декодировать исторический array и schema 2; сохранить deleted markers, не воскресить удалённую задачу. |
| `VoiceMoneyStore` | `files/voice-memory.bin`, magic `MV\x01`, AES-GCM; internal schema 1–2, export `memora-voice-memory-v2` | person/receipt/debt IDs, command IDs, точные minor units/currency, original source, recorded/occurred time и person links. Проверить обе поддерживаемые версии; неоднозначные имена не объединять, команды не переигрывать, связные ID сохранять. |

Реализации находятся в `apps/android/app/src/main/java/ai/memora/app/data/`. У каждого хранилища свой key provider; ключи нельзя переиспользовать для новой БД. Missing key, bad GCM tag, неизвестный header/schema или нарушенная ссылка должны остановить миграцию и сохранить старый источник, без создания пустой базы поверх ошибки. Пользовательский plaintext export VoiceMoney не считается переносом и не должен импортироваться автоматически. Settings/consent хранилища не входят в эти три доменных store и требуют отдельного inventory; системные backup Memora отключаются по решению владельца.

## Фактическая реализация P1 и результат synthetic probe

Schema v3 ввела P2 recovery journal: `apps/android/app/schemas/ai.memora.app.data.protectedstore.AgentDatabase/3.json`; текущая schema v6 — `apps/android/app/schemas/ai.memora.app.data.protectedstore.AgentDatabase/6.json`. Room 1→2→3 сохраняет command journal и добавляет metadata-only turn status; Room 3→4→5 — P3–P6 tables/schema history; 5→6 — явный money scope для исторических и новых записей. `ProtectedMemoryRepository` переносит legacy snapshots в одной SQLCipher Room transaction; `legacy_migration` хранит имя магазина, digest исходного **зашифрованного** файла, schema, число записей и verified-флаг, без текстового содержания. Повтор допускается только при совпадении всего manifest; непустая БД без manifest fail-closed. Task events повторно применяются через `TaskRules`; tombstones/deleted IDs, источники/ревизии и minor-unit amounts переносятся раздельно.

`DatabaseStorageProbe` запускается только отдельным instrumentation argument и использует собственные synthetic files/test key alias. На API 34 arm64 без сети проверены Capture internal schemas 1–5, Tasks historical JSON array + schema 2, VoiceMoney internal schemas 1–2, Room v1→v3 journal preservation, P2 unresolved command/turn status across database close/reopen, removal of resolved transient turn state, all-three-store transaction, matching retry, event replay, exact minor units, command collision rejection, outbox status и отсутствие test marker/SQLite header в закрытом DB. Синтетические файлы и тестовые ключи очищены. Это подтверждает только указанный AVD, не физическую модель телефона, все ABI или crash durability.

## Ключ нового хранилища

P1 создаёт независимый случайный 256-bit SQLCipher key. Для локального использования он хранится только как AES-GCM-wrapped blob, зашифрованный отдельным неэкспортируемым AES key Android Keystore; metadata и blob — в no-backup app-private storage. Keystore key alias имеет версию; ciphertext связан AAD с version/application purpose. При существующем DB без читаемого wrapped key не генерировать замену и не усекать базу: отказ/восстановление по явно выбранному владельцем экспорту. Биометрический prompt не требуется для фоновых напоминаний и не включается этим ADR. Возможность Keystore backup exclusion, аппаратного хранения, uninstall/reinstall, ротации ключа и восстановления проверить отдельно на устройстве P1; автоматический системный backup выключен согласно решению владельца.

## Порядок и границы перехода

1. Все три старых хранилища — источники данных, а не одна транзакция. Зафиксировать допустимые схемы, ID, сведения о версиях, точных денежных величинах, источниках, событиях, архиве и удалениях; неизвестные поля/форматы или недоступный ключ блокируют перенос. Не создавать вымышленные связи только по имени.
2. На синтетических данных проверить шифрование файлов БД/WAL/SHM, ключи, права файлов, отсутствие текста в логах и временных файлах, отказы ввода/вывода, потерю ключа и перезапуск. Получить проверяемый backup и manifest без содержания в журнале действий. Путь создания тестовой БД должен быть отдельным от пользовательских файлов.
3. Перед cutover остановить все старые пути записи, включая фоновые и голосовые. Создать новую БД отдельно и перенести данные с устойчивым сопоставлением ID. Сверить содержимое каждой версии и связи, а не только количество объектов; не вызывать LLM во время миграции.
4. До подтверждённой сверки активным остаётся старое хранилище. Атомарный маркер активного backend и manifest должны давать восстановление после уничтожения процесса на каждой стадии. После переключения нет двойной записи; после появления новых изменений возврат к старому состоянию требует отдельной безопасной процедуры, сохраняющей новые данные.
5. Не удалять старые файлы автоматически. Правила копий и удаления должны исключать незаметное восстановление удалённых записей; неизвестная актуальность tombstones — карантин. Резервный файл с Keystore-привязанным ключом не является переносимой копией между устройствами.

## Незакрытые решения и критерии проверки

P0 закрыт как проектный контрактный пакет; production-ready агент и live model evaluation отсутствуют. Синтетический путь legacy readers → coordinator → одна SQLCipher/Room transaction → сверка содержимого проверен на API 34. MEM-12.11 и пользовательский cutover не закрывать до физического Redmi/API 26, полного release ABI/package/license, key loss/restore/rotation, backup exclusion, WAL/SHM, corruption/disk-full, retry после остановки процесса, kill/restart/crash recovery и ручных workflow checks. Положительный unit или один API 34 probe не доказывают защищённость телефона или устойчивость при аварии питания.
