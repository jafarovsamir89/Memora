# ADR-012: локальное внимание и добровольные сводки

**Статус:** принято для нативного этапа M20-07, 2026-11-03. Основание: M20-07 в [мастер-поручении](../MEMORA_2_0_AGENT_MASTER_PROMPT.md), продуктовый раздел об attention engine в [спецификации](../MEMORA_2_0_PRODUCT_SPEC.md), [ADR-003](ADR-003-access-and-ownership.md), [ADR-006](ADR-006-retention-and-deletion.md) и [ADR-009](ADR-009-time-semantics.md).

## Решение

Двигатель внимания работает только по уже сохранённым локальным источникам: незавершённым задачам с реальным сроком, активным событиям календаря и открытым делам. Для открытого дела без срока можно показать существующий `nextAction`, но нельзя придумывать дату. Текущая схема долговых обязательств не содержит срока погашения, а записи не имеют отдельного состояния «ожидает ответа»; эти сведения не появляются в приоритетах, пока предметная модель не хранит их явно.

Предложения вычисляются детерминированно на устройстве и показывают ссылку на существующую запись. Уведомления отключены по умолчанию. Отдельное явное включение управляет ежедневной сводкой; пользователь задаёт местное время и тихие часы, может отложить сообщение на час или убрать его до следующего локального дня. Планирование использует неточный системный будильник и не обещает точную доставку. В тихие часы доставка переносится к их окончанию. После смены времени, зоны, загрузки системы и обновления приложения расписание вычисляется заново.

Настройки и даты отправки хранятся в новой таблице SQLCipher, добавленной миграцией 12→13; исходные задачи, дела и события не копируются и не изменяются. Только явный opt-in вместе с системным разрешением уведомлений допускает отправку. Push содержит фиксированный общий текст, а Android получает нейтральную публичную версию на lock screen. Имена, суммы, названия дел, сроки и содержание памяти в уведомление не входят. Облачный AI, микрофон и отправка памяти для сводки не используются.

## Время и повторы

Настройки содержат местное время суток, а не фиксированный UTC-интервал. Для пропущенного часа при весеннем переходе ежедневное сообщение сдвигается на первый существующий момент после разрыва; при повторном часе выбирается первый системный offset, а дневной ключ предотвращает второе сообщение. Поведение quiet hours и вычисление следующего сигнала тестируются независимо от системного AlarmManager. Неточный сигнал может опоздать из-за Doze/OEM; фактическая доставка подтверждается только на устройстве.

Каждая сводка допускается не чаще одного раза за местную дату. Явное snooze создаёт один дополнительный сигнал; если часовая отсрочка переходит через полночь, она становится единственной сводкой новой местной даты, а обычный сигнал этой даты подавляется. Dismiss блокирует доставку до следующей местной даты. Идентификатор уведомления стабилен, поэтому повторный системный сигнал обновляет ту же карточку. SQLCipher хранит только scope, настройки, локальные даты и время управления, не текст/снимок источников. Дата фиксирует вызов `NotificationManager.notify` для dedup; Android API не подтверждает, что пользователь увидел или прочитал уведомление.

## Проверяемая граница

Автоматические проверки подтверждают выбор кандидатов, порядок, область данных, тихие часы, DST, dedup, snooze/dismiss и сохранение синтетической строки через миграцию. Это не доказывает прохождение OEM-режимов или разрешение уведомлений на телефоне. При отсутствии permission либо недоступности SQLCipher сообщение не отправляется; состояние настройки сохраняется и остаётся доступно для исправления.
